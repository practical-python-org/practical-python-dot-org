## Why briefs instead of tutorials

Tutorials give you working code and the illusion of understanding. A brief gives you a target and
leaves the middle to you, which is where the learning is.

Every brief states what it should do, what counts as finished, and roughly how long it takes. None
of them include the solution.

## Contributing to either

Both halves take pull requests. Adding a brief is the easiest first contribution to this site — see
[contributing](../projects/our-projects/this-site.md) for how the site is built.
